## 已确认决策
| 决策 | 理由 |
|------|------|
| 图片上传到本机项目目录 | 用户接受当前本地优先方案；未来部署时可替换为对象存储 |
| 一个商品支持多个规格 | 满足颜色、电池、价格、SKU 和独立库存管理 |
| 商城刷新后立即看到后台修改 | 双应用直接共享 PostgreSQL，不引入额外实时推送复杂度 |
| 保留 DRAFT、ACTIVE、ARCHIVED 三态 | 支持草稿、上架、下架和重新上架 |
| 禁止批量删除 | 遵守项目 AGENTS.md |

## 错误记录
| 错误 | 尝试次数 | 解决方案 |
|------|---------:|---------|
| `apply_patch` 不允许同一补丁对同一路径先删除再新增 | 1 | 改为两个补丁：先删除单个明确文件，再新增同一路径 |
| `prisma generate` 在 Windows 上无法替换被运行中服务占用的引擎 DLL | 1 | 仅停止监听 3000/3001 的项目进程，生成和构建完成后恢复服务 |
| 后台构建提示动态上传路径扩大 Turbopack 追踪范围 | 1 | 路径已由服务端限制，按构建提示增加 `turbopackIgnore` 标记 |
| 生产商城对构建后新增的 `public` 图片返回 404 | 1 | 改为 `storage/product-images` 持久化目录，并由受限动态图片路由读取 |
| 修复补丁因 `.gitignore` 定位行不匹配未应用 | 1 | 读取真实文件末尾后按现有内容重新应用原子补丁 |

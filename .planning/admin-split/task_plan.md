# 任务计划：商城与管理员后台双应用拆分

## 关键问题
1. 当前后台代码与商城共享了哪些组件和服务端模块？
2. 如何在不确定部署平台时保持应用可独立部署且避免重复业务逻辑？

## 已做决策
| 决策 | 理由 |
|------|------|
| 同一仓库、两个独立 Next.js 应用 | 用户已确认；兼顾共享维护与独立部署 |
| 商城 3000、后台 3001 | 本地边界清晰，符合用户示例与期望 |
| 不批量删除文件 | 项目 AGENTS.md 明确禁止 |
| 根目录保留商城，新增 `admin-app/` | 最小化商城迁移风险，同时获得独立应用边界 |
| 后台独立 JWT Cookie，直接连接同一 PostgreSQL | 后台不依赖商城在线，未来可独立部署 |
| 商品查询显式等待请求时执行 | 后台修改后商城刷新即可读到新数据，无需跨应用缓存失效调用 |

## 遇到的错误
| 错误 | 尝试次数 | 解决方案 |
|------|---------|---------|
| PowerShell 组合 `rg` 查询因嵌套引号触发 ParserError | 1 | 拆分查询并使用单引号模式 |
| 商城类型检查引用已移除的 `/admin` 生成类型 | 1 | 停止旧 dev 进程并用 Next `typegen` 刷新生成文件 |
| `prisma generate` 无法重命名 Windows query engine DLL（EPERM） | 1 | 定位并停止仍持有本项目 Prisma DLL 的开发子进程后重试 |
| `node --env-file` 被 Next 构建 Worker 拒绝 | 1 | 使用官方 `@next/env` 在后台 Next 配置中加载仓库根 `.env` |
